# Versions and deployment

## Version

A **version** gathers stories that are finished, so that they can be put in front of real people together.

**Rule.** A version contains only [done stories](stories.md). Work in progress waits for the next one.

A version is named so that anyone can say which one they are talking about, and it lists what it changes in the words of the stories it carries.

## Deployment

A version is **planned**, then **deploying**, then **in real use** — or it **failed**, which is a state like any other and is said out loud.

**Rule.** A project always knows which version real people are using. A version nobody can name is a version nobody can fix.

## After real use

Once a version is in real use, the pull is always toward changing the application and telling the specification later. Then never.

**Rule.** A change in real use starts as a change to the [specification](specification.md), exactly as it did before. The order is the same on day one and in year five.

When the running application and the specification disagree, that disagreement is written down as an open [question](specification.md) until one side is corrected.
